Rytm tracks (SRC)

The machine each track reports over the Sidecar link, as the Rytm itself names it - not what Sidecar derives or what wt=voice:V and friends force. RYTM means the track is not ours: the Rytm plays it with its own analog or sample voice, so nothing Sidecar does affects it.

Wi-Fi

Network-

Sidecar uses one network at a time: Connect and save stores the network and restarts Sidecar on Wi-Fi (the sound stops for a few seconds; Ethernet is unused while it is on Wi-Fi). If it is not connected within 90 s, the previous setting comes back and Sidecar restarts on it (Ethernet, if Wi-Fi was off), so a wrong password cannot lock you out. This page follows to the Wi-Fi address at sidecar.local when this computer is on that network. The password is stored only as the network's key, never shown again; this page has no login yet; the pairing code under Access is what keeps someone else on this network out.

Access

Pairing code-
This device-

Sidecar shows an 8-digit code on the Rytm's screen and on its own screen (STATUS page, PAIR CODE). Entering it once lets this browser change things; reading the status and the log never needs it. A remembered device keeps working after Sidecar restarts, and Forget makes it ask for the code again. Forget every device also ends every other browser's and sdboot.py's access. The code is not encryption: this page is plain HTTP on your network, so treat the network itself as the lock.

Rytm MIDI bridge

Bridge-
Traffic-
Token

The Rytm's USB MIDI on TCP port 7330, for test tools on a computer (analogrun, analogusb.py, elkbench): everything the Rytm sends is copied to the tool, and the tool's messages go to the Rytm between Sidecar's own. It is off at every start, a tool must answer a challenge with the token (new at every turn-on), and Elektron OS upgrades and +Drive writes are refused unless the boxes above are ticked. On the computer run SIDECAR_BRIDGE_TOKEN=<token> python3 tools/rytm_bridge.py --pi sidecar.local and point the tool at tcp:127.0.0.1:7321 (docs/HARDWARE-TESTING.md). Forgetting every device turns the bridge off.

SD card speed

Verdict-
Measured-

Checks whether this card can stream multisamples (and record at the same time): about a minute, with a temporary file in /.rytm (up to 256 MB, removed afterwards). Run it while nothing plays: the sound may drop out while it runs. The result sets the streaming read-ahead and how many notes stream at once.

Storage

SD card-
Library-


      
USB drives (FAT32; a stick with the MBR scheme) mount when plugged in; Eject before pulling one.
        The bench writes and reads a 256 MB file on the drive (removed afterwards), then random reads, the raw device and
        reads while the Overbridge stream runs: a few minutes on the SD card, under a minute on a fast drive. It is refused
        while the Rytm plays or records; the sound may drop out while it runs on the SD card. Same as the console's
        stor=bench:USB; details in docs/STORAGE.md.

Send FX

      

      

      
What the Rytm's kit sets: each FX's type, where it returns (PRE on 2/3, POST on 0/1) and the 12 tracks'

LFOs
Eight LFOs on the Sidecar's voices (BD, BT, SD, LT, CH/OH, MT/HT, CY/CB, RS/CP: any parameter) or its send FX (FX1 / FX2
      P2..P5), on top of the Rytm's value; the value comes back when the LFO stops. Saved per kit, as the Rytm's own LFOs (switched with the Rytm's kit); the same on the Rytm's LFO page (TRK + YES).

The project's POOL: three lists (SAMPLES for GRANULAR, DSP SAMPLE and the sampler's takes;
      WAVETABLES for WAVETABLE; INSTRUMENTS for MULTISAMPLE), each 8 banks of 128 rows, row 000 OFF. The Rytm's bank
      list and the touchscreen show the same rows. Add files from the Files tab (+SMP / +WT / +INST, Fill bank).
      Replacing or unloading a row in use asks first, and is refused while the Rytm plays. Select unused picks the
      rows not seen playing in this project: a parameter lock on the Rytm that has not played yet is not known.
      Undo takes back the last replace or unload of the list. MISSING: the file is gone from the card (the row is
      silent); CHANGED: the file's content changed (Accept takes the new content).

USB stick

    
Export to a stick is off in this version (export to the card, then copy the
      bundle); import reads a bundle straight from the stick (its /SIDECAR or its root). Eject before you pull it.

    

    
Trash

    
A project's Sidecar files go here when its slot is cleared, deleted, pasted over or
      saved over on the Rytm, or deleted here; samples are never in it. The newest 64 are kept.
      

    

    
Export makes the bundle on the Sidecar a piece at a time on core 0, never on the audio core: while the
      Rytm plays it only reads, slowly (card writes wait for STOP), and while the recorder records it waits. Download
      streams it to this computer; very large bundles need a secure page (https or localhost) for the streaming download,
      otherwise the page collects it first (up to 1 GB). Importing never touches the Rytm: the summary says which Rytm
      project to load with Elektron Transfer and the name to save it under. On a card keyed by the Rytm's project slots
      (since 0.3.0) the import goes to a slot instead: pick it in the summary; the bundle holds only the Sidecar's
      side, so the Rytm's project must be in that slot (Transfer, or SAVE TO it before you import - a SAVE TO onto it
      afterwards moves the imported files to the trash). A slot with Sidecar files is only replaced when you tick
      replace: its files go to the project trash, restorable. Delete removes a project's Sidecar files only;
      its samples stay on the card.

  

  


  

  

    
Files

    
Go to
      
      
      
      

    

    

      
      
      
      
      

    

    

    

    
Drop files or folders on the list to upload them into this folder (folders whole, with their
      subfolders; .DS_Store and ._ files are left out). Uploads go one at a time in small pieces: the page runs on
      core 0 with the network, USB and the card, apart from the audio (render cores 1 and 2, control core 3).
      🔒 marks boot files and the restore backup (read-only); Samples, Plugins and .rytm themselves are kept
      (their contents can change). WAV files uploaded into GRANULAR (and one folder level below it), WAVETABLES or
      MULTISAMPLE are in the machines' browsers at once (rescanned after each upload). +SMP / +WT (any WAV
      or AIFF) and +INST (an .sfz) add the file to the project's POOL (SAMPLES, WAVETABLES or INSTRUMENTS), into
      the first free row of the POOL bank chosen above; a file already in that list keeps its row. Fill bank
      puts a folder's files into a bank's empty rows. The rows are in the Pool tab, the Rytm's bank list and the
      touchscreen; a row's audio is loaded into RAM when a voice plays it.

About

      

      
Sidecar | Expander, a sound engine beside the drum machine. Core 0 runs the network (this page),
        USB (Overbridge, USB-C) and the card; cores 1 and 2 render the voices and the send FX; core 3 is the control
        core (MIDI, machines, loading). The page never waits on the audio: a request is answered from what the
        cores last published.

    

  

  

    

      
Pairing code

      
Sidecar asks for a code before this page may change anything. It is on the Rytm's screen and on
        Sidecar's own screen (STATUS page, PAIR CODE), and it changes every time Sidecar restarts.

      

        

      

      

        

      

      

      
The status and the log are readable without the code, so you can watch Sidecar while it is
        unpaired. Several wrong codes lock pairing for a while.
